## 一、流程

1. **生成**：按 `docs/美术提示词.md` 对应条目出图，下载原图。
2. **上传**：二选一
   - 放进 `incoming/art/`，**保持目标相对路径**，例如
     `incoming/art/characters/reimu/normal.png`、`incoming/art/backgrounds/shrine.png`；
   - 或直接在对话里发图，并说明文件名（我会复制到 `incoming/art/` 对应位置）。
   - `incoming/` 已在 `.gitignore` 中，上传原图不会污染仓库。
3. **检测**：我按下方「验收标准」逐项检查（尺寸 / alpha / 文件名 / 构图 / 文字水印），
   结果回写到本表「状态」与「备注」。
4. **归档（通过）**：把该行从「待处理」移到「已归档」，记录日期与来源；同时覆盖
   `resources/images/` 下的旧占位文件。**旧占位需求即视为归档完成。**
5. **退回（不通过）**：状态改为 `↩️ 退回`，备注写具体原因（如「脚被裁」「输出 1024×1024」），
   你重生成后重新上传即可。

> 可以分批交，不要求一次交齐。每批通过即归档，未交的继续留在待处理。
> 立绘/头像必须透明；背景/CG 不透明即可，PNG/JPG 都收。

## 三、验收标准

### 3.1 自动检查（每张都跑）

```bash
# 文件类型 / 尺寸 / 通道
file incoming/art/characters/reimu/normal.png
magick identify -format "%wx%h %[channels]\n" incoming/art/characters/reimu/normal.png

# 立绘/头像：必须是 RGBA；背景/CG：RGB 或 RGBA 均可
```

| 类型 | 目标尺寸 | 通道 | 文件名 |
|---|---|---|---|
| 立绘 | 1200×1800 | RGBA | `characters/{id}/{expr}.png` |
| 头像 | 512×512 | RGBA | `avatars/{id}/{expr}.png` |
| 背景 | 1920×1080 | RGB / RGBA | `backgrounds/{scene}.png` |
| CG | 1920×1080 | RGB / RGBA | `cg/{角色}_{序号}_{主题}.png` |

### 3.2 人工检查（我会看，也会在游戏里核对）

- [ ] 立绘全身完整，脚没被裁，头顶留白 3~5%
- [ ] 透明边缘干净，没有灰边/绿边/白底残留
- [ ] 没有文字、签名、水印、UI 元素
- [ ] 五官对称，手指数量正常（能藏手就藏）
- [ ] 背景/CG 下缘 35~45% 没有重要信息（会被文本框遮住）
- [ ] 同角色不同表情的脸型、发饰、服装一致
- [ ] 色调与暗色 UI 协调，没有荧光饱和
- [ ] 游戏内实际跑对应剧本，构图与文本不打架

### 3.3 归档判定

- 自动检查 + 人工检查全部通过 → `✅ 已归档`
- 尺寸/透明/文件名任一不符 → `↩️ 退回`（可直接重新导出一张符合尺寸的，不必重画）
- 构图/文字/人物崩坏 → `↩️ 退回`（需要重生成）
