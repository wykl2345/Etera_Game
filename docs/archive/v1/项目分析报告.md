## 一、项目概述

**Etera_Game** 是一个基于 **Python + PySide6 + Lua** 的叙事游戏引擎（视觉小说引擎）。设计灵感来自 Emuera/ERA 类文字冒险游戏，核心特征是：

- **终端风格暗色 UI**：暗底亮字、等宽字体、选项嵌入文本流
- **Lua 脚本驱动**：Mod 作者用受限 Lua API 创作剧情，引擎暴露白名单指令集
- **角色立绘 + 状态系统**：好感度、属性、Flag 命名空间隔离
- **事件总线架构**：模块完全解耦，Mod 之间通过事件通信

**技术栈**: Python 3, PySide6 (Qt), lupa (Lua 绑定), PyYAML, Pygame (音频)

## 三、核心架构分析

### 3.1 架构分层

```
┌─────────────────────────────────────────────────────┐
│                   GUI 层 (PySide6)                   │
│  WindowManager → ConsoleWidget + ImageWidget        │
├─────────────────────────────────────────────────────┤
│                   引擎核心 (Core)                     │
│  ScriptScheduler ←→ LuaSandbox ←→ LuaAPI            │
├─────────────────────────────────────────────────────┤
│              状态 & 资源 & 事件                       │
│  GameContext + EventBus + SaveManager + ResourceMgr  │
└─────────────────────────────────────────────────────┘
```

### 3.2 脚本执行流程（协程调度器）

这是整个引擎最关键的设计。**不使用真正的 Lua 协程**，而是用 Qt 的 **嵌套 QEventLoop** 实现"暂停脚本等用户输入"：

```
[Lua 脚本调用 ui.ask_choice()]
        │
        ▼
[api_bridge._ui_ask_choice()]
        │
        ├──► event_bus.emit("ui.choice_show")  → ConsoleWidget 显示选项
        │
        └──► scheduler.wait_for_choice()
                │
                └──► QEventLoop.exec()  ← 嵌套事件循环，Qt 仍能处理点击
                        │
                        │  用户点击选项...
                        ▼
                ConsoleWidget._resolve_choice()
                        │
                        ├──► event_bus.emit("ui.choice_made")
                        │       │
                        │       └──► scheduler.resolve_wait(choice_index)
                        │               │
                        │               └──► loop.quit()  ← 退出嵌套循环
                        │
                        └──► wait_for_choice() 返回结果给 Lua
```

**关键设计决策**: 嵌套 QEventLoop 确保在等待用户输入时，Qt 主线程事件循环仍在运行，窗口不冻结。

### 3.3 事件总线 (EventBus)

- 发布-订阅模式，支持同步/异步两种 emit
- 系统事件（引擎自动触发）vs 游戏事件（脚本主动触发）
- 优先级排序、事件过滤、一次性订阅、传播停止
- 事件历史记录（最近100条）

### 3.4 Lua 安全沙箱

- 基于 `lupa` 库
- 移除危险全局: `os`, `io`, `debug`, `loadfile`, `loadstring`, `dofile`, `require`, `package`
- 限制 `math.randomseed`
- 内存限制 256MB，执行时间限制 30秒
- 降级方案: `MockLuaRuntime`（lupa 不可用时）
- 脚本验证器: 执行前正则扫描危险模式

### 3.5 状态管理 (GameContext)

分层命名空间设计：
```
GameContext
├── world          → day, time_of_day, location, season, weather
├── player         → stats (StatBlock), inventory (Inventory)
├── characters     → {reimu: CharacterState, marisa: CharacterState, ...}
│   └── CharacterState → id, name, stats, flags, relation, location
└── global_flags   → {core, story, coffee_mod, mushroom_test, ...}
    └── FlagStore  → 每个命名空间独立存储
```

**关键特性**: `core` 命名空间受保护，脚本不可直接写入，防止 Mod 破坏引擎状态。

### 3.6 存档系统

- **格式**: 版本化 JSON（非 pickle）
- **迁移链**: 1.0→1.1→1.2→1.3（已注册4个迁移类）
- **原子写入**: 临时文件 + rename
- **自动备份**: 最多5个历史备份
- **20个存档槽位** + 快速存档（槽位0）

## 八、代码质量评估

### 优点
1. **架构清晰**: 三层分离（引擎/数据/资源），模块职责单一
2. **文档齐全**: 4份设计文档 + DSL参考手册 + 代码注释完整

3. **废弃组件**: choice_widget.py 和 log_widget.py 已被 console_widget.py 替代，但未清理
4. **测试缺失**: 无单元测试，仅有3个Lua集成测试脚本
5. **错误处理**: 部分模块的错误处理较粗略（exc_info=True 日志 + 吞掉异常）
6. **setup.py / requirements.txt 缺失**: 无依赖清单文件
